# workflows-check

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

A pull request can edit any workflow in its own repository, the one that
checks it included. [workflows-check](../.github/workflows/workflows-check.yml)
is instead required by an organization ruleset: GitHub runs it from this
repository at the ref the ruleset pins, so no pull request in the target
repository can change or skip it. It needs no secrets and only
`contents: read`.

It reads the pull request's files as Git blobs, from a clone it never
runs anything of, and refuses the pull request when:

| Refused | The threat it stops |
| --- | --- |
| A job the [shape check](#shape-check) refuses | A job that runs untrusted steps or an agent unsandboxed, or with a broad token |
| A workflow that gains a `pull_request_target` or `workflow_run` trigger | A workflow that runs with the base branch's token and secrets on input the author controls |
| An added line with a `zizmor: ignore` comment (in any case or spacing), in a workflow, an `action.yml` or `.github/dependabot.yml`, other than `# zizmor: ignore[self-repository]` on a `uses: ./...` line | A pull request silencing the audit that would flag what it adds |
| A change to zizmor's configuration (`zizmor.yml` or `.github/zizmor.yml`) | The same, for every file at once |
| A change to actionlint's configuration (`.github/actionlint.yaml` or `.yml`) | The same for actionlint, whose `paths` ignores can silence every error in a workflow |
| A `.gitignore`, at any depth, that gains a pattern or loses a `!` negation | A workflow hidden from zizmor, whose default collection skips what `.gitignore` matches, tracked files included |
| In a file with a job or step whose `uses:` names `workflows-check.yml`, any change to that job (its `uses`, `if`, `needs`, `with` and the rest) or to the file's `on:`, a removal included | A repository's own call of this check repointed at a weaker one, or turned off by an `if:` or a trigger that never fires: a skipped required job reports success |

The lint action's zizmor also collects with `--collect=all`, which skips
nothing `.gitignore` matches; the `.gitignore` rule is for a repository
whose pin of the lint action predates that, and it judges only changed
`.gitignore` files, so a workflow force-added under a pattern already on
the base branch is still hidden from such a pin.

The trigger, ignore, `.gitignore` and reference rules judge only what the pull request
changes from its merge base; what is already on the base branch was
reviewed there. The one ignore allowed is the one agentic-job's ingress
check allows: zizmor's `self-repository` audit flags every local `./`
action and workflow call. It is matched as the whole line, not by its
place in the YAML, so a misplaced one silences no more than that audit
on that line.

What it does not stop, and review still has to: a line added within the
span of an ignore already on the base branch (zizmor applies an ignore to
the whole finding it is on, a `run:` block say), a change to a workflow
file the base already exempts from the shape check, and the other events
that run with the base branch's secrets on input others write
(`issue_comment`, `pull_request_review`, `issues`), which the review
workflows here need. Nor does it stop a job that a repository's call of
this check `needs` being made to fail or skip, through a script it runs
or the file's `defaults` say, which skips the call too: call it from a
job with no `needs`, in a file of its own, as
[the fixture](tests/workflows-check/caller.yml) does, which also keeps
other changes to the file from being refused with it.

## Shape check

The job shape check is agentic-job's `workflows check` (its
[rules](https://github.com/cgwalters-forge/agentic-job/blob/main/docs/workflows-check.md)),
run as the release binary [shape-check.yml](shape-check.yml) names and
refused unless its SHA-256 matches. It reads the pull request's workflow
files and the exemptions in `.github/agentic-job/workflows.toml` of the
**base** commit, so that a pull request cannot exempt itself: a new
exemption applies from the pull request after the one that adds it.

## Opting out

A repository cannot: there is no input, variable or file in the target
repository that turns a rule off. Exempting a workflow file from the shape
check is a reviewed change to that repository's base branch, as above. An
exception to the other rules, or a repository left out of the ruleset, is
a change here. A pull request that must make a refused change (adding a
reviewed `pull_request_target` workflow, say) is merged by an organization
owner bypassing the ruleset.

## The ruleset

An organization owner creates it under the organization's Settings, Rules,
Rulesets, New branch ruleset:

- Enforcement status: **Evaluate**, until its results on open pull
  requests look right; then **Active**.
- Target repositories: **All repositories** (or a listed set to start).
- Target branches: **Default branch**.
- Rules: **Require workflows to pass before merging**, with workflow
  `.github/workflows/workflows-check.yml` from this repository at a
  **commit SHA**, never a branch or tag: this repository's tags are not
  protected, so anyone who can push here could move one past review.
  Moving the pin to a new revision of this file is how a change here takes
  effect.
- Bypass list: organization owners only.

A repository with a merge queue gets the check on `merge_group` too. The
workflow checks itself out with the target repository's token, so this
repository has to stay readable to every repository the ruleset targets
(public, as it is now). The `job.workflow_repository` and `job.workflow_sha`
it does that by are new; the first evaluate-mode runs are where to confirm
that they name this repository, and the workflow fails if they are empty.

## Locally

From the root of a clone that holds both commits:

```sh
BASE=$(git rev-parse origin/main) HEAD=$(git rev-parse HEAD) \
  just --justfile path/to/actions/lint/Justfile --working-directory . workflows-check
```

It exits 0 when nothing is refused, 1 when something is, and 2 when it
could not run. `just test-lint` runs its tests, with the fixture workflows
in [tests/workflows-check](tests/workflows-check/).
