# app-token

> This text was generated by an LLM ([how cgwalters uses LLMs](https://github.com/cgwalters/cgwalters#llms)). cgwalters has not reviewed it yet.

Mints one role's GitHub App installation token with a pinned
[actions/create-github-app-token](https://github.com/actions/create-github-app-token),
scoped to the named repositories of one owner, and masks it. Each role
(status, review, implement/fix, supervisor executor) has an app of its
own, so a comment, review or push says which step wrote it, without a
long-lived PAT (cgwalters-forge/tracker#766).

```yaml
- uses: cgwalters-forge/actions/app-token@main
  id: app
  with:
    app-id: ${{ vars.STATUS_APP_ID }}
    private-key: ${{ secrets.STATUS_APP_PRIVATE_KEY }}
    owner: cgwalters-forge
    repositories: tracker
    permission-issues: write
- run: gh issue comment "$ITEM" --body done
  env:
    GH_TOKEN: ${{ steps.app.outputs.token }}
```

`repositories` and at least one `permission-*` input (`actions`,
`checks`, `contents`, `issues`, `pull-requests`, `statuses`, `workflows`)
are required: without them upstream would grant every repository the
installation reaches, with all of the app's permissions. The action's
token lasts an hour and is revoked when the job ends. Mint it only in a step that
runs no agent or other untrusted code; agents keep the read-only job
token.

## Steps longer than the token

A step that may run past the hour gets a fresh token from `remint.mjs`,
whose path is the `remint` output, before each call or batch of calls.
It keeps the last token in a file of its own in `$RUNNER_TEMP` (mode
0600) and mints again only when that one has five minutes or less left.
After a call returns 401, call it once with `--unauthorized`, which mints
again however long the kept token had left, and retry that call once.
Every later step of the job runs as the same user and could read the
file, so end the step with `--revoke`, which removes and revokes it (a
failed revocation is tried again by the next `--revoke`):

```yaml
- run: |
    trap 'node "$REMINT" --revoke' EXIT
    api() {
      local token
      token=$(node "$REMINT") || return
      GH_TOKEN=$token gh api "$@" > out.txt 2> err.txt && { cat out.txt; return; }
      grep -q '(HTTP 401)' err.txt || { cat err.txt >&2; return 1; }
      token=$(node "$REMINT" --unauthorized) || return
      GH_TOKEN=$token gh api "$@"
    }
    for item in $ITEMS; do api "repos/cgwalters-forge/tracker/issues/$item" > "$item.json"; done
  env:
    REMINT: ${{ steps.app.outputs.remint }}
    APP_ID: ${{ vars.STATUS_APP_ID }}
    PRIVATE_KEY: ${{ secrets.STATUS_APP_PRIVATE_KEY }}
    OWNER: cgwalters-forge
    REPOSITORIES: tracker
    PERMISSION_ISSUES: read
```

`PERMISSION_*` (`PERMISSION_PULL_REQUESTS` for `permission-pull-requests`)
should match the action's inputs, so the new token has no more than the
first. The step holds the private key for that, so it has to be a step the
first rule above already admits. A token replaced near expiry or after a
401 is not revoked; it had five minutes left at most, or no longer
worked. Calls at once that each mint keep only the last token, and the
others are not revoked either, so call it from one process at a time. The script mints only when called: nothing renews tokens in the
background, and a long-lived process that holds a token in its
environment is not covered.
